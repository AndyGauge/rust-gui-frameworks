Native Shell (NSH) comes from **Longbridge**, the team that already maintains `gpui-component` (now `gpui-kit`), the most widely used widget library on top of Zed's gpui. Its repository opened on 14 October 2026. NSH is the newest version of an old idea: one component tree rendered with **each platform's own widgets**. On iOS that means UIKit, on Android Android views, on macOS AppKit, on Windows Win32 with Direct2D, and on Linux GTK 4. The web gets HTML. Two further backends are new: GPUI, so an NSH screen can sit inside a gpui app, and a terminal backend drawn with ratatui.

::inline rust | label=examples/tasks-rs (illustrative, not compiled)
#[component]
pub fn App() -> impl IntoElement {
    view()
        .flex_1()
        .bg(move || theme().background)
        .child(shell::shell())
}
::end

Apps can be written in Rust, in TSX, or in both. The TSX path is what makes NSH unusual. It embeds a QuickJS JIT and the `oxc` compiler, so an app can load TSX screens **at run time** as signed packages, sandboxed by its host. Longbridge pitches this for plugins, features shipped without an app-store update, and UI generated by AI. Styling uses Tailwind classes, and the docs publish an `llms.txt` for models.

::inline tsx | label=examples/bench/TsButton.tsx, abridged (illustrative, not compiled)
export function Button(props: ButtonProps): JSX.Element {
  return (
    <View onPress={() => props.onPress?.()} role="button"
          accessibilityLabel={props.accessibilityLabel ?? props.title}
          class={`${base} ${variants[props.variant ?? "primary"]}`}>
      <Text class="text-[16px] font-semibold">{props.title}</Text>
    </View>
  );
}
::end

In its `Cargo.toml`, the shared layer that survives is Taffy **0.15**, used for flexbox and grid on every platform. Text, input and accessibility come from each platform, which is the point of native views. wgpu **29** appears for the GPU backends. NSH is not on crates.io. You install an `nsh` CLI, and Rust apps currently build with a fork of Cargo (`huacnlee/cargo`). That is a significant requirement for a Rust library, and worth checking before adopting it. It is the most ambitious project on this page, and also the hardest to evaluate from the outside.
