FerroUI takes an approach no other framework in this book takes. It is a **port** of Avalonia, the cross-platform C# toolkit modelled on WPF, that keeps Avalonia's architecture, contracts and behaviour so that its apps, themes and XAML carry over. It first appeared on crates.io on 15 October 2026, and ten releases later it was at 0.4.0. The README records that every upstream member in scope has a Rust counterpart or a documented waiver: 30,354 present and 5,856 waived.

::code ferroui-app/src/bin/one.rs

The code looks unlike anything else in this book, and that is intended. Avalonia is object-oriented. Applications subclass `Application`, controls are retained objects with properties, events and child collections, and styling uses selectors and control themes. FerroUI rebuilds that class hierarchy in Rust with macros (`ferro_class!`) and `*Impl` traits for the virtual methods. It comes with what a WPF developer expects: data binding, a XAML compiler that turns markup into Rust in a build script, Fluent, WinUI 3, macOS 26 and Material themes, developer tools on F12, and MVVM libraries. Version 0.4 added a second way to write UI: `ferroui-view`, with an `rsx!` macro, signals and React-style hooks.

Its lockfile is the most independent in this book, with 189 packages and **none of the shared layers**: no winit, no wgpu, no Taffy, no Parley and no AccessKit. Rendering goes through Skia (`skia-safe` **0.153.3**, with Vello as an experimental alternative backend), text shaping through HarfBuzz, and each platform has its own window, input and accessibility layer (UI Automation on Windows, AT-SPI on Linux). The first build downloads a prebuilt Skia and compiles HarfBuzz with a C++ compiler. The README is unusually precise about how it was tested: in CI, VMs, the iOS simulator and the Android emulator, but "not on a range of real devices", and no screen reader has been checked.
